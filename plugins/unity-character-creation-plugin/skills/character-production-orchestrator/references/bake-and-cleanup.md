# Deterministic bake, pixel cleanup and frame-bank import

Use the connected Unity Editor and actual supported APIs. Implement bake tooling in the target project's Editor directory and verify it there; this reference is a recipe, not a claim that an exporter already ran. Read `hybrid-pipeline.md`, ANIMATION_SPEC.md and FRAME_BANK_SPEC.md.

1. Work in a duplicate/bake scene with the calibrated direction rig and desired item. Record source/clip/item revisions. Use a fixed orthographic camera, common output canvas and ground anchor, native resolution/PPU, transparent RGBA clear, appropriate sprite materials and controlled lighting. Avoid unwanted anti-aliasing/rescaling. Check actual transparency, color space and edge fringe in the exported PNG.
2. Establish one pose schedule per action/direction. Fixed FPS is a simple default; 12 FPS is a proposed starting point. For a duration T and N evenly timed loop frames use t=i*T/N, i=0..N-1 and record actual FPS N/T. A 0.5s/12-FPS loop has N=6 and no repeated t=T image. Noninteger T*FPS needs a documented adjusted N/FPS or explicit schedule, not silent drift. A one-shot specifies its sample times and terminal hold/return; markers retain semantic time, independent of frame quantization.
3. Sample the authoring clip deterministically against the direction rest pose via appropriate Editor Animation APIs. Freeze gameplay/physics/automatic direction changes. Every equipment appearance uses exactly the same source poses/timestamps; capture all passes at a given pose before advancing. Never rely on wall-clock recording to assign frame indices.
4. Render transparent passes with real occlusion semantics. Simply hiding all other renderers exposes pixels that should be occluded in the final composition. Define pass splitting, matching masks/occluders or appropriate precompositing for interleaved Body/Weapon/Armor pieces. Verify final composite against the fully equipped reference pose. A label saying "Weapon_Front" does not itself solve hand occlusion.
5. Save full-canvas raw PNGs under a stable Action/Direction/Appearance/Pass/frame index naming scheme. Record source pose index/time, dimensions, pivot, PPU and optional per-frame hand/FX anchors. Save/restore camera, source pose, renderer visibility/materials, animation mode and temporary objects even if export fails. Never modify the production scene silently or hand-write Unity YAML.
6. Inspect EVERY exported frame at 1:1: silhouette, hidden seams/caps, head/hand/foot anatomy, clothing coverage, aliasing/outline/palette, grip, alpha and loop continuity. Retouch using actual supported pixel/art tools. Do not regenerate unrelated standalone images per pose. Keep Raw/ and Final/ separate with revision/evidence; final art changes propagate to matching masks/occlusion and equipment checks.
7. Import Final/ via the Unity asset-import stage. Point filtering, consistent PPU/pivots, correct alpha/rectangles and verified crop offsets remain required. Full-canvas is the first implementation; introduce trimming/atlasing only after reconstruction alignment passes.
8. Build/validate frame-bank mappings across required items/actions/directions. Never fill missing required frames with arbitrary other action/direction images. Empty optional gear is explicit. Run layered continuous playback, loop seams, state/direction/item transitions and low-FPS marker tests before validated status.

Bake produces pixel images, not automatically clean pixel art. Finite frame cleanup can repair sampled silhouettes, but source rig holes should also be corrected where reusable production depends on them. No exported bank or gameplay success is claimed without actual files/captures.
